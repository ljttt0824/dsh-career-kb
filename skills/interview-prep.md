# 技能：面试准备（interview-prep）

## 目标

围绕一个具体岗位，把「JD + 个人证据 + 公开面经」变成可以背、可以练、可以现场用的面试材料：自我介绍、复习清单、题库、项目深挖、情景题、短板应对、反问。

## 输入

- 必须：岗位 JD 或岗位名（公司 + 岗位）。
- 可选：轮次（一面/二面/HR）、面试日期、时长、已有面经链接、想重点练的部分。

## 流程

1. **确认岗位与轮次**：没有 JD 时，用公司+岗位做通用准备并明确标注「通用准备，非该岗官方流程」。
2. **读知识库**（列出实际检索范围）：
   - `02-求职与实习`：申请记录、投递台账、旧简历、旧面试准备、面试复盘
   - `04-项目与成果沉淀`：项目主档、实习成果
   - `03-能力建设与学习`：技能笔记、八股、方法论
   - `05-个人背景与经历`：画像、偏好、教育背景
   - `01-职业规划与目标`：职业动机与阶段目标（用于「为什么这个岗/这家公司」）
3. **联网面经**（只有工具可用时才做）：
   - 用 `web_search` 搜「公司 岗位 面经 一面/二面 2025/2026」「岗位 面试题」
   - 记录标题、链接、来源性质（官方/个人分享）、查询日期；面经只作「可能问题线索」，不能当成确定流程或标准答案。
   - 没有联网工具时明确写「未进行联网检索，本材料仅基于 JD + 知识库」。
4. **JD 要求 → 个人证据 → 缺口**：先做矩阵，再写自我介绍；没有证据的要求留缺口，不用同义改写伪装匹配。
5. **写材料**（模板 `templates/interview-prep.md`），至少包含：
   - 来源清单（JD / 个人记录 / 简历版本 / 面经，分别标性质与限制）
   - JD 逐点拆解 + 匹配话术（每条：JD 原意 → 我的证据 → 一句话回答）
   - 公司/行业/岗位理解（客户、场景、竞争、技术路线；区分事实与分析）
   - 自我介绍：1 分钟版 + 3–5 分钟逐字稿（每句个人事实可追溯）
   - 复习清单（主题、来源、掌握程度、优先级、自测）
   - 题库：
     - 八股/专业基础（概念 → 我的理解 → 项目中的用法 → 常见追问）
     - 常规题（动机、优缺点、职业规划、团队冲突）
     - 项目深挖（每个项目：背景/职责边界/关键决策/困难/结果口径/如果重做）
     - 情景题（按岗位：客户调研、需求优先级、项目延期、跨团队推进、数据分析）
   - 短板与证据缺口：真实短板 + 如实回应 + 补足动作
   - 反问 3–5 个（按轮次筛选）
   - 红线（不做的表达：夸大、抢功、贬低他人、编造数据）
   - 模拟面试记录表 + 终检清单
6. **模拟模式**：用户说「模拟面试」时，一次只问一道，等回答后追问，不提前给参考答案；结束后按「结构、证据、岗位相关性、表达」给反馈，不预测录用结果。
7. **保存**：
   - 本机：`02-求职与实习/面试准备/YYYY-MM-DD-公司-岗位-面试准备.md`
   - 飞书（可用时）：`feishu_doc` 新建文档；长文档可拆「主文档 + 题库表」；回填链接。
8. **读回核对**，报告路径、缺什么、下一步练什么。

## 事实与表达要求

- 项目数字必须带口径（自建测试集/线上/样本量/时间范围）和来源；没有就定性描述。
- 自我介绍先说「我能为这个岗位提供什么」，再说经历；技术岗可先技术，商业/售前岗先客户价值。
- 每个项目准备一句 30 秒版：我怎么做 + 能提供什么；技术细节等追问。
- 面经里的「标准答案」只能参考，不能当成该公司流程。

## 输出检查

- [ ] 自我介绍里每句事实都能在知识库找到来源。
- [ ] JD 每条要求都有「证据 / 缺口」结论。
- [ ] 八股题答案没有把网上说法写成确定事实；版本敏感内容标日期。
- [ ] 项目题没有超出证据的职责、规模、数字。
- [ ] 短板是真实存在且与岗位相关的，不是「假缺点」。
- [ ] 联网/未联网状态已说明；面经附链接与查询日期。

## 正反例

**好**：JD 要求「跨团队推进」，回答引用实习里「对接研发/检测/供应商三方、倒排计划跟进节点」的事实，并说明没有可核实的按期率数据，不编数字。
**不好**：JD 要求「熟悉 PMO 体系」，直接写「精通 PMO 全流程，主导过 5 个千万级项目」——无来源、夸大。

更多见 `examples/fewshot-interview-prep.md`。
