# 技能：搭建职业生涯知识库（setup）

## 什么时候用

用户第一次使用、说「搭建我的职业知识库」「建档」「初始化」，或知识库为空、只有收件箱时。

## 原则

1. 先利用已有材料（简历、旧笔记、本次陈述），不要重复问已知信息。
2. 一次只问一个问题，允许跳过、暂停、先出草案。
3. 事实、推断、建议、待补充分开写；不确定就标出来。
4. 写入后读回核对，报告真实路径。

## 步骤

1. 调用 `career_status`，确认数据目录与现有记录。
2. 读取 `_meta/settings.md`，了解来源收件箱与已有偏好。没有就按默认。
3. 先问 5 个关键问题（不要一次全问）：
   - 当前阶段与身份（在校/实习/在职/转行，方向）
   - 最紧急的目标与时间约束
   - 已有材料位置（简历、项目文档、旧知识库）
   - 偏好的知识库形态（本机 Markdown / 飞书知识库 / 两者）
   - 需要重点沉淀的模块（求职、能力、项目、行业）
4. 需要更完整画像时，再分批补充：教育背景、实习/工作经历、项目、技能、偏好与约束、资源、职业价值观。参考 `references/intake` 的 25 个信息点，但不要机械问完。
5. 生成两份核心文档并保存：
   - `05-个人背景与经历/个人画像/个人画像.md`（用模板 `templates/profile.md`）
   - `01-职业规划与目标/长期规划/职业规划.md`（用模板 `templates/career-plan.md`，覆盖近期到 20 年，远期标为可修订情景）
6. 调用 `career_apply`（kind=create）写入；或直接 `career_save` 到收件箱再整理。推荐直接创建正式文档，避免二次整理。
7. 重建索引：调用 `career_reindex`（若工具清单没有，调用 `/career` 页面的重建按钮或直接调用 `career_verify` 触发）。
8. 输出：两份文档路径、六大模块说明、仍缺信息、下一步一个动作、三个示例指令（`/career-save`、`/career-resume`、`/career-audit`）。

## 交付检查

- [ ] 画像与规划都引用了用户提供的事实，没有编造学历/时间/数字。
- [ ] 规划区分事实、推断、建议。
- [ ] 首页 `index.md` 覆盖新文档。
- [ ] 报告里明确「已生成 / 已保存」的区别。

## 正反例

**好**：用户说「我在读研，想做 AI 产品，明年毕业」。建档时只问缺失项，画像写「在读研究生（方向：AI 产品），毕业时间 2027 年（用户陈述）」，规划写「近期：补齐产品实习与作品集；中期：AI 产品经理；远期：可修订」。

**不好**：把「AI 产品」自动补成「3 年大厂 AI 产品经理经验」，或把「明年毕业」写成具体月份。用户没说的，不写。
