# 技能：存入与整理（capture）

## 目标

把用户随手刷到、剪藏、粘贴、选中的资料，整理成「可学习、可复习、可复用」的知识卡，放进正确的模块；能查重、能追源、能同步飞书。

## 输入来源

1. 命令后面的文字：`/career-save <内容或链接>`。
2. 对话中选中的文字（浏览器浮动按钮 / 右键菜单）→ 已存入收件箱，路径会在消息里给出。
3. 来源收件箱目录：读取 `_meta/settings.md` 的「来源收件箱」；没有配置就先问用户，不扫描整台电脑。
4. 用户上传的文件、截图、网页链接。

## 处理流程

1. 读取 `_meta/settings.md`；确认来源目录、排除项、目标根目录。没有配置时只处理本次输入。
2. 逐条读取内容。链接打不开、需要登录、只有标题时，标「未读取」，不要根据标题猜正文。
3. 判断主要用途和稳定对象，选择唯一主分类：
   - 技术教程、概念/认知框架、方法经验、他人经验 → `03-能力建设与学习`（子目录按现有结构，没有就放模块根并注明子类待定）
   - 具体岗位 JD、面经、简历、面试准备/复盘、投递 → `02-求职与实习`
   - 用户亲历的项目事实、实习成果、作品 → `04-项目与成果沉淀`
   - 个人画像、偏好、约束 → `05-个人背景与经历`
   - 行业趋势、市场数据、公司/赛道观察 → `06-行业洞察与社会感知`
   - 未来目标、方向、行动计划 → `01-职业规划与目标`
4. 查重：用 `career_search` 搜标题关键词与主题词。
   - 完全重复：不新建，把新来源补到已有主记录。
   - 同主题新增观点：在已有记录上追加「补充（来源/日期）」。
   - 观点冲突：两边都保留，标注来源与日期，标「待核实」，不自动合并。
5. 写知识卡（模板 `templates/captured-knowledge.md`）：
   - 前置字段：id、title、type、module、source、source_url、author、published、captured、updated、review_after、confidence、tags
   - 正文：一句话摘要（区分原作者观点 / 可核实事实 / AI 归纳）、核心内容、适用条件与限制、可学习、可复习（3–5 道主动回忆题+答案+来源）、可复用（步骤/清单）、用户自己的实践（没有就写「尚无个人应用记录」）、来源与核验表、后续动作。
6. 保存到对应模块目录，文件名 `YYYY-MM-DD-简短主题.md`。调用 `career_apply`（kind=create）或 `career_save` + 整理；写入后 `career_read` 读回。
7. 重建索引：`career_apply` 会自动重建；否则提示用户或调用 `career_verify`。
8. 飞书同步（仅当 `career_status` 显示 feishu.available=true）：
   - 用 `feishu_wiki` 找到目标知识库/节点，或用 `feishu_doc` 新建文档；
   - 写入知识卡正文，标题带日期与主题；
   - 截图、附件用 `feishu_drive` 上传后嵌入文档；表格类知识可选用 `feishu_bitable` / `feishu_sheet`；
   - 返回文档链接，写进知识卡 frontmatter 的 `feishu_url`，并报告给用户。
   - 没有飞书工具时明确说「仅保存到本机」，不要假装已同步。

## 输出格式

```
已存入 N 条：
1. 标题 → 路径（模块）
   来源：平台/作者/日期；读取状态：完整/部分/未读取
   飞书：链接 或 未同步（原因）
跳过 N 条：标题 → 原因（重复/无法读取/分类不明）
```

## 真实性红线

- 他人观点 ≠ 事实；未核实数据标「来源主张 / 待核实」。
- 他人经历 ≠ 用户经历；不能写进 04 或用户画像。
- 没有读到的正文，不生成摘要和复习题。
- 不擅自新建一级目录；主分类不明确时列 2–3 个候选并询问。
- 「存入」只授权新增/补充，不授权删除、移动或改写原始剪藏。
