# 技能：JD 定向简历（resume）

## 目标

根据岗位 JD，在知识库里找出**可核实的**项目、技能、实习/工作经历和历史简历版本，生成针对该岗位的简历；宁可留缺口，不编造。

## 输入

- 必须：岗位 JD（原文；没有就请用户粘贴）。
- 可选：公司/岗位名、目标地点、简历格式偏好（一页/两页）、截止日期。

## 流程

1. **拆 JD**：提取职责、硬性条件（学历/专业/年限/技能）、优先条件、关键词；记录 JD 来源、日期、版本。输出一张「JD 要求表」。
2. **检索证据**（每类都列出实际查过的范围）：
   - `career_search` 搜 JD 关键词、项目名、技能名；
   - 读 `04-项目与成果沉淀`：项目档案、实习复盘、作品；
   - 读 `03-能力建设与学习`：技能记录、方法论；
   - 读 `05-个人背景与经历`：画像、教育、偏好；
   - 读 `02-求职与实习/简历版本`：历史简历，**只作版本与措辞参考，不能单独证明经历**。
3. **建证据矩阵**（模板 `templates/resume-evidence.md`）：每条 JD 要求 → 证据原文/摘要 → 来源路径/ID → 状态（已确认/用户回忆/推断/无证据）→ 可写入的表述 → 缺口。
4. **写简历**：只使用状态为「已确认」的事实。
   - 经历按与 JD 的相关性排序，不按时间堆砌；
   - 每条 bullet：动作 + 方法/工具 + 结果（有证据才写数字，并标口径）；
   - 技能只写真实使用深度：「熟练/使用过/了解」要和证据一致；
   - 不写的：没做过的职责、没拿到的证书、别人的成果、推测的团队规模。
5. **真实性检查**（模板里的 checklist 全过一遍）。任何一项过不了，删除或标「待核实」，不能留在可投递正文。
6. **保存**：
   - 本机：`02-求职与实习/简历版本/YYYY-MM-DD-公司-岗位-简历.md`
   - 飞书（可用时）：用 `feishu_doc` 新建文档，或 `feishu_drive` 上传 PDF/Markdown；把链接回填到简历记录。
   - 保存后读回。
7. **交付**：简历正文 + 证据矩阵 + 缺口清单 + 一句「哪些内容必须本人核实」。

## 真实性红线

- 不编造职位、任职时间、职责范围、团队规模、客户、工具熟练度、成果数字、因果关系。
- 没有量化数据就写定性结果（「缩短了人工核对步骤」），不要补百分比。
- 旧简历、模型旧草稿都不是事实来源。
- 简历里的每个项目名词，都能在 `04` 找到对应主档或用户本次确认。

## 输出结构

```
## 目标岗位
公司 / 岗位 / JD 来源 / 日期

## 证据矩阵（表）
JD 要求 | 类型 | 证据与来源 | 状态 | 可写入表述 | 缺口

## 简历正文（Markdown）
...

## 缺口与待核实
- ...

## 来源
- 04-.../项目A.md
- 02-.../简历版本/2026-09-旧版.md（仅措辞参考）
```

## 正反例

**好**：「负责课程知识图谱流水线，把知识点抽取准确率从 50% 提升到 90%（来源：04/项目档案/知识图谱.md，指标口径：自建测试集 200 条）」。
**不好**：「主导千万级用户产品的知识图谱建设，准确率 95%」——没有来源、夸大规模、改数字。

更多正反例见 `examples/fewshot-resume.md`。
