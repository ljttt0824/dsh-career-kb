# 技能：面试复盘（interview-review）

## 目标

把一次真实面试的「问题—当时回答—反馈—结果」沉淀成经验与改进行动，关联申请、简历版本和项目证据；不把事后分析写成当时的原话，也不把猜测写成面试官事实。

## 输入（缺什么问什么）

- 公司 / 岗位 / 申请记录 / 轮次
- 面试日期、形式（电话/视频/现场）、时长
- 面试问题与自己的回答（原话或转述）
- 面试官反馈（原话/转述）、可观察信号（追问、打断、表情）
- 结果（通过/挂/待定/无回复）与通知时间
- 自己的感受与判断

## 流程

1. 在 `02-求职与实习` 找对应申请记录、投递台账、简历版本、项目主档；没有就记录缺失。
2. 用模板 `templates/interview-review.md` 建复盘文档：
   - 基本信息与信息来源（本人即时记录/事后回忆/其他）
   - 问题表：问题 | 当时回答（原话或标「转述」）| 可观察反馈 | 对应证据 | 待核实
   - 面试官明确反馈（只记录确认过的）
   - 可能关注点（标「推断」+ 依据 + 置信度）
   - 做得好的点（证据）
   - 回答缺口（哪一步没讲清：结论/证据/数字口径/结构）
   - 建议答案（事后改写，只用已确认事实；新增信息单独标注）
   - 改进行动：动作 | 依据 | 完成标准 | 目标日期
   - 知识库更新：关联/新增/待确认
3. 把可复用经验沉淀：
   - 通用方法 → `03-能力建设与学习/方法论`
   - 岗位/公司信息 → `02-求职与实习/面试复盘` 或 `岗位库`
   - 新的事实/更正 → 新增来源记录；**未经确认不覆盖**已有项目事实或画像。
4. 如果复盘产生下一轮准备需求，追加到对应「面试准备」文档的「二面准备」章节，并说明依据。
5. 保存后读回，报告路径与待确认项；飞书可用时同步文档并回填链接。

## 真实性规则

- 原话只有用户明确说是原话时才加引号；回忆性转述标「转述」。
- 面试官心理、录用概率、公司内部原因都标「推断」，不写成事实。
- 不预测录用结果；不制造「假复盘」来迎合用户。
- 失败不等于能力否定，区分「岗位匹配/信息不足/表达问题/硬性条件」。

## 输出结构

```
## 基本信息
## 面试流程回顾（按环节）
## 问题与回答（表）
## 面试官反馈（原话/转述）
## 做得好的 / 回答缺口
## 下次改进（可执行动作 + 完成标准）
## 建议答案（事后改写）
## 关联与更新
```

## 正反例

**好**：记录「面试官说：行业认知需要再补一些（原话）」→ 改进动作「按客户方向做 3 家前沿 AI 公司的技术路线/算力需求调研，产出 1 页笔记」。
**不好**：把「面试官可能觉得我太技术」写成面试官原话，或直接判定「这公司不要我，因为学历」。

更多见 `examples/fewshot-interview-review.md`。
