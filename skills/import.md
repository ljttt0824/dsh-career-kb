# 技能：导入已有知识库（import）

## 目标

把用户**现有的**职业资料（飞书知识库 / 云文档 / 本地目录 / IMA 导出）迁移进本机职业档案：保留原目录语义、来源链接和原文，不丢信息、不重复、不改写事实。

## 先确认来源

1. **飞书知识库**：`feishu_wiki` → `list_spaces` 找到空间，`list_nodes` 递归列节点；文档用 `feishu_doc get_raw_content` 读正文；附件用 `feishu_drive` 看清单。
2. **飞书云空间文件夹**：`feishu_drive list_files` 递归列出，文档读正文，表格/多维表格按需导出。
3. **本地目录**：直接扫描（Markdown / 文本 / PDF / docx）；PDF 用可用的本地工具读取，读不了就标「未读取」。
4. **IMA 或其他无 API 的知识库**：让用户导出 Markdown/PDF 到一个目录，再按本地目录处理；不要声称能直接操作 IMA 文件夹。

## 流程

1. 先列清单：来源、节点数、类型、可读性。不要一上来全量写入。
2. 建**目录映射表**（来源目录 → 六大模块），给用户确认：
   - 职业规划/目标 → 01
   - 求职/简历/面试/投递 → 02
   - 学习/技能/方法论 → 03
   - 项目/实习/作品 → 04
   - 个人背景/画像 → 05
   - 行业/趋势 → 06
   没把握的列候选，不新建一级目录。
3. 先导 1 个目录做样板（≤ 10 篇），读回给用户看格式是否满意，再继续。大库分批，每批 ≤ 20 篇。
4. 每篇写入：
   - frontmatter：`id`、`title`、`type`、`module`、`source`（飞书/本地）、`source_url`（飞书链接或原路径）、`captured`（导入日期）、`original_path`（保留原目录）
   - 正文：原文照录（可保留标题层级），**不要**把摘要替换原文；摘要放「一句话摘要」小节并标明「Agent 归纳」。
   - 文件名：`YYYY-MM-DD-原文件名.md`，保留原目录作为子目录（若六大模块下没有该子目录，放模块根并在 frontmatter 记 `original_path`）。
5. 查重：每篇先 `career_search` 标题与关键词；重复则把新来源补到已有主记录，不新建。
6. 读回核对：抽查 10% 的页面，确认标题、来源、正文长度、frontmatter。
7. 重建索引（`career_reindex`），报告：
   - 已导入 N 篇（路径列表）
   - 跳过 M 篇（重复 / 未读取 / 分类不明）
   - 失败 K 篇（原因）
   - 下一步建议：`/career-audit` 巡检、补画像、建投递台账。

## 边界

- 不删除、不移动、不改写飞书或本地原件；只读取。
- 读取失败（权限、登录、格式）就列「未处理」，不根据标题猜内容。
- 个人隐私数据只进本机 `%DSH_HOME%/storages/career-kb`，不要写进公开仓库。
- 飞书文件夹层级的新建/重命名/跨库移动受 API 限制；做不到时给人工步骤。

## 正反例

**好**：飞书知识库「02-求职与实习/面试准备」下 6 篇文档 → 先导 2 篇样板，确认后按原目录导入 `02-求职与实习/面试准备/`，frontmatter 写飞书链接与导入日期，读回核对。

**不好**：把飞书文档全部丢进 `00-收件箱` 就宣布「已导入」；或把原文删改成 200 字摘要，导致面试细节丢失。
