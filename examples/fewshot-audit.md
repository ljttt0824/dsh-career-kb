# 整理巡检 Few-shot 与正反例

> 虚构示例。展示「只读扫描 → 确认清单 → 用户确认 → 执行 → 读回」的完整链路。

## 场景 A：完全重复

**扫描结果（节选）**

```json
{
  "kind": "exact-duplicate",
  "severity": "high",
  "title": "完全重复：RAG 三路召回笔记",
  "paths": [
    "03-能力建设与学习/学习笔记/2026-03-02-RAG三路召回.md",
    "03-能力建设与学习/学习笔记/2026-03-02-RAG三路召回-副本.md"
  ],
  "evidence": "正文哈希 8f2a1c9d3e 相同",
  "suggestedAction": { "kind": "merge", "from": ["…-副本.md"], "into": "…RAG三路召回.md" }
}
```

**正例汇报**

> 发现 1 组完全重复（正文 100% 一致）：
> #8f2a1c9d · RAG 三路召回笔记
> - A：03/学习笔记/2026-03-02-RAG三路召回.md（有 3 条补充来源）
> - B：03/学习笔记/2026-03-02-RAG三路召回-副本.md（无补充）
> - 建议：保留 A，合并 B 后归档；执行前自动备份。
> 回复「执行 #8f2a1c9d」即可。

**用户确认后**

```
career_apply({
  actions: [{ kind: "merge", from: ["03-…/RAG三路召回-副本.md"], to: ["03-…/RAG三路召回.md"] }],
  confirm: true
})
```

**反例**
- 扫描后直接删除副本，没有给清单，也没有备份。
- 因为文件名带「副本」就当作完全重复，没核对正文。

## 场景 B：近似重复 / 冗余

**正例**
> #b7d2e4 · 两条「费曼学习法」记录重叠 82%：
> - A（2025-11，3000 字，有 2 个来源）
> - B（2026-02，1200 字，只有 1 个来源，内容基本被 A 覆盖）
> 建议：B 合并进 A，保留 B 的来源链接；risk：低，可逆。

**反例**
- 只按标题相似就合并；或把 B 里「不适用于技能类学习」的限制丢掉。

## 场景 C：过时

**正例**
> #c91f0a · 「2024 大模型 API 价格对比」超过 18 个月未更新（type=行业信息）。
> 建议：① 更新价格并标日期；② 若不再维护，归档到 `_meta/archive`。
> 不直接删除：历史对比仍有参考价值。

**反例**
- 因为「日期旧」就删除历史项目记录或旧简历版本。

## 场景 D：冲突

**正例**
> #e42a7b · 疑似矛盾：
> - 记录 A（2025-12，来源：官方文档）：某指标上限是 128
> - 记录 B（2026-03，来源：个人博客）：该指标上限是 256
> 建议：并列两条来源与日期，标「待核实」，用户确认后再更新；不自行选边。

**反例**
- 直接把 B 的数字改成 A，或把两条合并成「上限约 128–256」。

## 场景 E：归类错误

**正例**
> #f3a9c1 · 「某岗位 JD 逐条拆解」当前在 `03-能力建设与学习`。
> 依据：内容主要是具体岗位要求与投递判断，预测模块 `02`（命中 9 次）。
> 建议：移动到 `02-求职与实习/岗位库/`，保留原路径链接。

**反例**
- 因为文中有「学习」二字就留在 03；或新建「求职资料」一级目录。

## 场景 F：收件箱积压

**正例**
> 收件箱 7 条未整理。建议先运行「存入与整理」，逐条分类；不要在一次巡检里批量写卡。
> 若用户同意，我可以在下一轮按 capture 技能处理，并报告每条路径。

**反例**
- 把收件箱文件直接批量移动到 03，不读内容、不查重。
